# 儿童学习资源 Skill 套件 · 系统架构说明

## 一、系统定位

本套件是一套**面向儿童学习资源全流程处理的分层 Skill 系统**，实现从用户需求到归档复用的完整闭环：

> 用户提出需求 → 深度拆解 → 平台路由 → 多端搜索召回 → 质量筛选 → 用户选择 → 分级下载获取 → 归档入库复用

**核心目标**：搜得到、抓得到、选得好、管得住。

**适用范围**：覆盖 8 大儿童学习资源品类——学科同步、科普启蒙、人文历史、语言表达、思维训练、艺术美育、习惯品格、兴趣拓展。

### 架构设计思想

- **调度与执行分离**：调度层只负责路由和汇总，执行层负责具体平台的实现
- **平台能力内聚**：同一个平台的搜索、下载、反爬、登录，全部内聚在一个 skill 里
- **统一接口规范**：所有平台 skill 遵循相同的输入输出格式，调度层无差别调用
- **通用兜底机制**：有专属 skill 的走平台通道，没有的走通用通道，支持渐进式演进

## 三、各 Skill 职责边界

### 第一层：流程编排层

#### 1. learning-resource-flow（总调度入口）

| 项目 | 说明 |
|------|------|
| **定位** | 整个套件的唯一入口，负责流程编排与状态管理 |
| **输入** | 用户原始需求（自然语言） |
| **输出** | 最终交付结果（资源文件 + 元数据 + 归档信息） |

**核心职责**：
1. 按顺序调用各 Skill，串联完整业务流程
2. 管理流程状态与上下文数据传递
3. 处理异常、回退与降级策略
4. 统一向用户反馈进度与最终结果

**不做什么**：
- 不处理具体的搜索、下载、归档等业务逻辑
- 不保存业务数据，只保存流程状态

---

### 第二层：业务能力层

#### 2. resource-intent（需求理解与查询生成）

| 项目 | 说明 |
|------|------|
| **定位** | 把用户的自然语言需求翻译成结构化的搜索指令 |
| **输入** | 用户原始需求（自然语言） |
| **输出** | 结构化查询指令包 |

**输出内容（结构化）**：
- 核心主题
- 目标年龄范围
- 难度偏好（入门/进阶/系统）
- 资源形态偏好（视频/音频/文档/图文）
- 来源偏好（官方优先/视频平台优先/不限）
- 分级查询列表（核心/官方/形态/长尾，四级）
- 搜索模式（标准模式 / 穷尽模式）

**核心能力**：
1. 需求澄清（最多 2 轮，避免过度追问）
2. 语义理解与槽位抽取
3. 五维拆解生成多组查询
4. 查询分级与优先级排序

---

#### 3. resource-search（搜索策略生成器）

| 项目 | 说明 |
|------|------|
| **定位** | 搜索的"军师"——不负责实际搜索，只负责想清楚"去哪些平台、搜什么关键词" |
| **输入** | intent 输出的结构化查询指令包 |
| **输出** | 各平台搜索任务清单（带优化后的关键词、搜索参数、预期召回数量） |

**核心职责**：
1. **需求分析与主题分类**：判断需求类型（科普/学科/语言等），匹配最佳平台组合
2. **平台路由判断**：根据需求特点 + 平台优势图谱，决定去哪些平台搜索
3. **关键词优化**：针对每个平台的搜索特性，优化生成最合适的搜索关键词
4. **查询分发**：为每个平台生成独立的搜索任务（关键词、数量、参数）
5. **搜索策略制定**：根据搜索模式（标准/穷尽）调整搜索深度和广度

**关键数据依赖**：
- 平台优势图谱（各平台擅长什么领域）
- 平台-Skill 映射表（平台名 → 对应 skill 名称）
- 各平台搜索能力说明

---

#### 4. resource-selector（候选展示与用户选择）

| 项目 | 说明 |
|------|------|
| **定位** | 把候选资源展示给用户，供用户选择 |
| **输入** | resource-platforms 输出的候选资源列表 |
| **输出** | 用户选定的资源列表（带链接、平台标识、元数据） |

**核心能力**：
1. 结构化展示（按平台/类型/质量分级分类展示）
2. 标注下载难度与可行性预估（高/中/低）
3. 支持用户多选、筛选、排序
4. 记录用户选择结果

---

#### 5. resource-downloader（下载调度器）

| 项目 | 说明 |
|------|------|
| **定位** | 下载的"大脑"，只负责调度，不负责具体下载 |
| **输入** | 用户选定的资源列表（带链接、平台标识） |
| **输出** | 下载完成的本地文件列表（含元数据、状态） |

**核心职责**：
1. **任务分发**：根据平台标识，把下载任务分发给对应的 platform skill
2. **通用兜底**：没有对应 platform skill 的，走通用下载工具
3. **进度跟踪**：跟踪每个下载任务的状态（排队/下载中/成功/失败）
4. **失败重试**：根据错误类型，按策略自动重试
5. **降级处理**：多次失败的，走降级路径（提取摘要、保存链接等）
6. **结果汇总**：汇总所有下载结果，统一返回

**关键规则**：
- 统一错误码体系（`NETWORK_*` / `ANTI_CRAWL_*` / `AUTH_*` / `CONTENT_*` / `PARSE_*` / `DOWNLOAD_*` / `SYSTEM_*` 等，完整列表见 `shared/schemas/error-codes.md`）
- 分级重试机制（不同错误类型不同重试策略）
- 四级降级路径（完整版本 → 预览版本 → 核心摘要 → 来源链接）

---

#### 6. library-manager（归档入库管理）

| 项目 | 说明 |
|------|------|
| **定位** | 把下载好的资源整理入库，方便后续复用 |
| **输入** | 下载完成的文件 + 元数据 |
| **输出** | 归档后的资源索引信息 |

**核心能力**：
1. 分类归档（按主题、类型、年龄等维度）
2. 标签管理与自动打标
3. 本地资源索引建立
4. 重复资源检测与去重

---

### 第三层：平台执行层

#### resource-platforms（平台执行总入口）

| 项目 | 说明 |
|------|------|
| **定位** | 所有平台能力的统一入口，接收搜索任务后实际执行搜索，并负责结果汇总与质量筛选 |
| **输入（搜索模式）** | 各平台搜索任务清单（来自 resource-search） |
| **输出（搜索模式）** | 统一格式的候选资源列表（带平台标识、质量分级、下载预估） |
| **输入（下载模式）** | 资源链接 + 下载参数 |
| **输出（下载模式）** | 下载完成的本地文件路径 + 元数据 + 状态 |

**核心职责**：
1. **多平台并行搜索**：调度各平台脚本执行搜索
2. **结果汇总**：汇总所有平台返回的搜索结果
3. **跨平台去重**：基于内容指纹、URL、标题相似度进行去重
4. **质量筛选**：过滤付费、非中文、广告等低质量内容
5. **质量评估与分级**：按五维评分体系对资源进行质量评级（S/A/B/C）
6. **排序输出**：按质量、相关性排序，输出最终候选列表

#### 各平台子模块

每个平台都包含以下模块，由 resource-platforms 统一调度：

| 模块 | 说明 |
|------|------|
| 🔍 搜索模块 | 该平台的专属搜索技巧、排序逻辑、结果解析 |
| ⬇️ 下载模块 | 该平台的专属下载方法、工具配置、参数调优 |
| 🛡️ 反爬应对模块 | 该平台的反爬特点、应对策略、重试机制 |
| 🔑 登录态管理模块 | 该平台的登录方式、Cookie 管理、鉴权处理 |

**平台必须遵守的规范**：
1. 返回结果必须符合统一资源元数据格式
2. 错误必须返回统一错误码
3. 搜索结果必须包含「下载可行性预估」（高/中/低）
4. 搜索结果必须包含「平台自评质量分」

## 四、标准工作流程

### 完整流程（6 大阶段）

```
阶段一：需求理解与澄清
  └─ learning-resource-flow 接收用户原始需求
  └─ 调用 resource-intent 进行需求分析
  └─ resource-intent 分析需求（必要时进行最多 2 轮澄清）
  └─ 输出结构化查询指令包
  └─ 返回给 flow

阶段二：搜索策略生成
  └─ flow 调用 resource-search
  └─ search 分析需求类型与特点
  └─ 根据平台优势图谱进行平台路由判断
  └─ 针对每个平台优化搜索关键词
  └─ 生成各平台搜索任务清单
  └─ 输出搜索任务计划
  └─ 返回给 flow

阶段二（执行）：平台搜索执行与结果筛选
  └─ flow 调用 resource-platforms
  └─ 调度各平台脚本并行执行搜索
  └─ 汇总所有平台返回的搜索结果
  └─ 跨平台去重（内容指纹 + URL + 标题相似度）
  └─ 初筛过滤（付费/非中文/广告等）
  └─ 质量评估与分级（S/A/B/C 四级）
  └─ 按质量、相关性排序
  └─ 输出候选资源列表
  └─ 返回给 flow

阶段三：候选展示与用户选择
  └─ flow 调用 resource-selector
  └─ selector 结构化展示候选列表（标注下载难度）
  └─ 用户选择需要的资源
  └─ 输出选定资源列表
  └─ 返回给 flow

阶段四：下载调度与获取
  └─ flow 调用 resource-downloader
  └─ downloader 按平台分类下载任务
  └─ 分发任务给 resource-platforms 执行 + 通用下载兜底
  └─ 跟踪每个任务的下载进度
  └─ 失败时按策略自动重试
  └─ 多次失败走分级降级路径
  └─ 汇总所有下载结果
  └─ 返回给 flow

阶段五：归档入库
  └─ flow 调用 library-manager
  └─ library-manager 分类归档、自动打标签
  └─ 建立本地资源索引
  └─ 重复资源检测与去重
  └─ 输出归档结果
  └─ 返回给 flow

阶段六：结果交付
  └─ flow 汇总所有结果
  └─ 统一格式交付给用户
```

> **说明**：资料库检索不作为标准流程的必经步骤，用户需要时可主动调用 library-manager 查询。

## 五、关键设计原则

### 1. 策略与执行分离原则

策略层（resource-search）只负责想清楚"去哪些平台、搜什么关键词"，不负责实际执行搜索。
执行层（resource-platforms）负责实际执行搜索、汇总结果、去重、质量筛选。
调度层（resource-downloader）只负责下载任务的调度和汇总，不负责具体下载实现。

> **好处**：各司其职，便于独立优化和扩展，新增平台不影响策略层逻辑，策略调整不影响执行层。

### 2. 平台能力内聚原则

同一个平台的搜索、下载、反爬、登录，全部放在同一个 platform skill 里。

> **好处**：共享登录态和反爬策略，维护成本低，内聚性高，修改一个平台的逻辑不影响其他平台。

### 3. 统一接口规范原则

所有 platform skill 的输入输出格式必须统一，错误必须用统一错误码。

> **好处**：调度层可以无差别地调用所有 platform skill，新增平台只需加映射，不用改调度逻辑。

### 4. 通用兜底机制原则

有 platform skill 的走专属通道，没有的走通用通道。
- 搜索兜底：通用搜索引擎（百度、必应）
- 下载兜底：通用下载工具（yt-dlp、wget、requests）

> **好处**：不会因为缺少某个 platform skill 就完全用不了，支持渐进式演进，先做价值最高的平台。

### 5. 穷尽召回 + 用户选择原则

搜索阶段尽量多搜，把选择权交给用户，而不是模型提前过滤掉大部分。
只过滤明显垃圾的，质量一般的也保留并标注等级。

> **好处**：用户能看到更多选项，找到最适合自己需求的资源，而不是被模型替自己做决定。

### 6. 最大化提取 + 分级降级原则

能拿完整不拿摘要，能拿原文件不拿转换格式。
下载失败时逐级降级，不直接放弃。
降级内容必须明确标注「非完整版本」。

> **好处**：尽量保证有东西可用，而不是完全失败，提升整体成功率。

### 7. 儿童友好优先原则

- 默认只保留中文内容（英语学习等明确需求除外）
- 默认过滤付费/VIP 内容
- 所有资源必须经过儿童友好度评估
- 高风险、违法违规、盗版内容直接过滤

## 六、调用规范与注意事项

### 1. 调用入口规范

必须通过 `learning-resource-flow` 统一入口调用，禁止跳过 flow 直接调用下层 skill。

### 2. 数据传递规范

- 上层 skill 的输出必须完整传递给下层 skill，不得随意丢弃字段
- 新增字段必须向后兼容，不得破坏现有字段含义
- 元数据格式变更必须同步更新共享规范文件

### 3. 错误处理规范

- 所有 skill 遇到错误时，必须返回明确的错误类型和错误信息
- 可恢复的错误必须标注是否可以重试、建议重试次数
- 不可恢复的错误必须说明原因和建议的降级方案

### 4. 渐进式演进规范

- 平台 skill 不需要一次性全部做完，缺哪个平台就先用通用兜底
- 优先做资源量大、价值高的平台（P0 → P1 → P2）
- 新平台 skill 上线后，只需更新「平台-Skill 映射表」即可生效，无需修改调度层

### 5. 质量评估规范

采用「平台自评 + 平台层统一校准」的两级质量评估机制：
1. 各平台脚本对自己返回的结果先自评（最了解自己平台的情况）
2. resource-platforms 再根据跨平台统一标准做汇总校准和排序

质量等级：S（强烈推荐）/ A（优质推荐）/ B（可用推荐）/ C（谨慎推荐）

> 📖 全系统统一的质量评估标准（五维评分、权重、等级映射、前置过滤等）定义在 `shared/schemas/quality-rubric.md`，所有平台的质量评分均以该文件为唯一权威。
