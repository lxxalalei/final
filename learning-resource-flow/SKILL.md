# learning-resource-flow · 总调度入口

## 概述

本 Skill 是儿童学习资源 Skill 套件的**唯一总入口**，负责协调整个资源获取工作流：
从用户提出需求开始，经过需求拆解、平台路由、多端搜索召回、用户选择确认、分级下载获取，最终归档到本地资料库。

本 Skill 不直接执行搜索或下载，而是调度各专业 Skill 协同完成任务。


## 适用场景

当用户提出以下类型的需求时，应触发本 Skill：

- "给孩子找一些数学练习资料"
- "找恐龙科普视频和阅读材料"
- "给8岁孩子找四则混合运算练习题"
- "找小学三年级数学下册同步课件"
- "把这个页面的资料保存到资料库"
- "我之前存的拼音资源还有吗"
- "给孩子找些古诗听的音频"

---

## 核心原则

1. **用户确认优先**：展示候选后等待用户确认，不静默下载
2. **最少必要澄清**：只追问会显著改变结果的缺失信息，最多 2 轮
3. **穷尽召回 + 用户选择**：尽量多搜，把选择权交给用户
4. **最大化提取 + 分级降级**：能下完整不拿摘要，失败时逐级降级
5. **归档便于复用**：下载的资源自动归档，后续可主动检索复用
6. **儿童友好**：默认只保留中文、免费、适龄的内容

## 数据流转规则

> 各阶段输出通过 JSON 文件保存到工作目录，不堆积在上下文中。

### 1. 创建会话

收到新需求时：
- 生成 session_id：`{日期}-{时间}-{主题英文缩写}`，如 `20260626-1441-math-grade3`
- 创建目录：`.learning-resource-work/sessions/{session_id}/`
- 创建子目录：`downloads/`
- 写入 `manifest.json`：

```json
{
  "session_id": "20260626-1441-math-grade3",
  "user_request": "帮我找三年级数学练习题",
  "status": "in_progress",
  "current_stage": 1,
  "stages": {
    "stage1": {"status": "pending", "output": "stage1_intent.json"},
    "stage2": {"status": "pending", "output": "stage2_search.json"},
    "stage3": {"status": "pending", "output": "stage3_select.json"},
    "stage4": {"status": "pending", "output": "stage4_download.json"},
    "stage5": {"status": "pending", "output": "stage5_archive.json"}
  }
}
```

### 2. 调度每个阶段

对阶段 1→2→3→4→5 依次执行：
- 更新 manifest.json：当前阶段标记为 `in_progress`
- 调用对应 Skill，传递三个参数：会话目录路径、上游文件名、输出文件名
- Skill 返回后：只读输出文件的 `_summary`，不读完整 data
- 更新 manifest.json：当前阶段标记为 `completed`，回填 summary
- 根据 summary 决定下一步

### 3. 上下文管理

上下文中只保留 session_id、当前阶段、各阶段 summary。需要展示给用户时（如候选列表），从文件读取 data 部分后渲染。

### 4. 需求类型判断

| 用户说的 | 处理方式 |
|---------|---------|
| 新的搜索/下载主题 | 创建新会话，从阶段一开始 |
| "刚才那个""加选几个" | 复用当前 session_id，从指定阶段继续 |
| "我之前存的""上次下载的" | 调用 library-manager 查资料库（不碰 sessions/） |
| "继续上次没下完的" | 列出 sessions/ 目录让用户选，从中断处继续 |

> 搜索结果是时效性数据，每次新需求都重新搜索。

## 协作的 Skill 清单

| Skill | 所在层 | 职责 | 调用阶段 |
|-------|-------|------|---------|
| `resource-intent` | 业务能力层 | 需求理解与查询生成 | 阶段一 |
| `resource-search` | 业务能力层 | 搜索调度（路由+汇总+质控） | 阶段二 |
| `resource-selector` | 业务能力层 | 候选展示与用户选择 | 阶段三 |
| `resource-downloader` | 业务能力层 | 下载调度（分发+重试+降级） | 阶段四 |
| `library-manager` | 业务能力层 | 资源归档、索引、管理 | 阶段五 |
| `resource-platforms` | 平台执行层 | 具体平台的搜索+下载 | 阶段二、四（由调度层调用） |

> **注意**：platform skill 由 search 和 downloader 调度器直接调用，flow 不直接调用 platform skill。
> 
> **说明**：资料库检索不作为标准流程的必经步骤，用户需要时可主动调用 library-manager 查询。

## 完整工作流（6 个阶段）

### 阶段一：需求理解与澄清

**目标**：把用户的自然语言需求翻译成结构化的搜索指令

**步骤**：
1. 调用 `resource-intent` 分析用户需求
2. intent 进行需求澄清（最多 2 轮）
3. intent 输出结构化查询指令包
4. flow 确认任务定义，告知用户采用的假设

**输出格式**：
直接渲染输出（不加代码框）：

📋 任务确认
主题：[学习主题]
年龄/年级：[年龄或年级]
目标：[启蒙/预习/复习/练习/拓展]
资源类型：[视频/音频/文档/练习题/综合]
搜索模式：[标准模式 / 穷尽模式]
假设说明：[如有默认假设，在此说明]

---

### 阶段二：搜索调度与召回

**目标**：通过多平台并行搜索，穷尽召回相关资源

**步骤**：
1. 调用 `resource-search`（搜索调度器）
2. search 进行平台路由判断（查平台优势图谱 + 平台映射表）
3. search 分发查询给各 platform skill + 通用搜索兜底
4. 各平台 skill 执行搜索，返回带自评质量分的结果
5. search 汇总结果、跨平台去重、初筛过滤
6. search 做跨平台质量校准与分级（S/A/B/C）
7. search 按质量、相关性排序，输出候选列表

**候选数量**：
- 标准模式：20-25 个候选
- 穷尽模式：30-40 个候选

**每个候选包含**：
- 资源标题、平台标识、来源链接
- 质量等级、下载可行性预估
- 内容简介、适龄范围、标签
- 播放/浏览量、时长等平台数据

---

### 阶段三：候选展示与用户选择

**目标**：让用户了解候选资源并选择要获取的内容

**步骤**：
1. 调用 `resource-selector`
2. selector 结构化展示候选列表（按平台/类型/质量分级分类）
3. 每个候选标注下载难度（高/中/低）
4. 用户选择需要的资源（支持多种选择方式）
5. selector 输出用户选定的资源列表

**选择方式**：
- 编号选择（单个/多个/范围）
- 全部选择
- 按类型筛选
- 按质量筛选
- 取消选择

**展示格式示例**：
直接渲染输出（不加代码框）：

🔍 为您找到 22 个优质资源，按质量从高到低排序：

📺 B站视频（8个）
1. ⭐ S级：小学必背古诗文动画（228集）
   难度：⚠️ 中（可能需要重试）
   播放：500万+ | 时长：共228集
   推荐理由：动画形式，孩子容易接受，覆盖小学全部必背古诗
   链接：https://www.bilibili.com/video/BV1xx...

...

💡 选择方式：
- 回复数字编号（如：1,3 或 1 3）
- 回复"全部"下载所有
- 回复"视频"只选视频类
- 回复"S级"只选S级
- 回复"不要了"取消下载

---

### 阶段四：下载调度与获取

**目标**：获取用户确认的资源并保存为本地可管理形态

**步骤**：
1. 调用 `resource-downloader`（下载调度器）
2. downloader 按平台分类下载任务
3. downloader 分发任务给各 platform skill + 通用下载兜底
4. 跟踪每个任务的下载状态（排队/下载中/成功/失败）
5. 失败时按错误类型自动重试（参考统一错误码体系）
6. 多次失败走分级降级路径（完整→预览→摘要→链接）
7. 汇总所有下载结果

**下载结果分类**（与 `download_status` 字段对应）：
| 用户可见状态 | download_status | degraded_level | 说明 |
|------|------|------|------|
| ✅ **完全下载** | `success` | Level 0 | 成功获取原始文件 |
| ⚠️ **部分下载** | `degraded` | Level 1/2 | 降级获取：预览版/部分章节/核心摘要 |
| ❌ **下载失败** | `failed` | Level 3 | 只保留标题+链接+简介 |

> 说明：早期版本的「转换保存」已归并到 `degraded`，由 `degraded_level` 和 `degraded_content` 字段区分具体降级形式。

**重要原则**：
- 不静默失败，每个资源都有明确结果
- 失败原因用统一错误码
- 降级内容明确标注「非完整版本」
- 不破解付费墙，不绕过登录授权

---

### 阶段五：归档与索引

**目标**：将成功获取的资源整理到本地资料库，便于后续复用

**步骤**：
1. 调用 `library-manager` 执行归档
2. **归档前去重检查**（自动）：检测与已有资源的跨平台重复
   - 三层策略：内容指纹（精确）→ URL 结构化 → 标题相似度（近似）
   - 按 `dedup.strategy` 处理（默认保留最高质量版本）
   - 重复资源跳过归档或标记，避免资料库膨胀
3. 按学科/年龄段/主题分类存放
4. 更新资源索引（主索引 + 标签索引）
5. 记录完整的资源元数据（来源、获取时间、适龄范围等）

**归档目录结构**：
```
学习资料库/
  数学/
    小学三年级/
      四则混合运算/
        B站-系统讲解视频.mp4
        K5Learning-练习题.pdf
  语文/
    小学一年级/
      古诗/
        喜马拉雅-宝宝巴士古诗词.mp3
  科普/
    恐龙主题/
      ...
  待确认/
    ...
```

---

### 阶段六：结果反馈

**目标**：清晰告知用户获取结果和资源位置

**输出格式**：
直接渲染输出（不加代码框）：

✅ 资源获取完成

✅ 成功获取（X个）：
1. [资源名] → [保存路径]
2. ...

⚠️ 部分成功（X个）：
1. [资源名] → 原因：[只下载了前5集]
   保存位置：[路径]

⚠️ 已降级保存（X个）：
1. [资源名] → 原因：[付费内容，无法下载]
   已保存：标题 + 简介 + 来源链接
   ⚠️ 非完整版本

📁 资源已归档到：[资料库路径]
🔍 下次搜索类似需求时会优先复用这些资源

## 异常处理

### 用户取消
任何阶段用户说"算了""不要了""取消"，都立即终止流程，友好回复。

### 搜索结果太少
如果搜索结果少于 5 个，主动询问用户：
- 是否放宽条件？
- 是否换个关键词？
- 是否开启穷尽模式？

### 下载全部失败
如果所有资源都下载失败：
- 说明失败原因
- 提供降级内容（摘要、链接）
- 询问是否需要换其他资源

## 边界与限制

### 可以做的
- 搜索国内公开互联网的教育资源
- 下载公开可访问的文件
- 转换网页内容为本地可管理形态
- 使用用户本人的登录态访问平台
- 管理和复用本地资料库

### 不可以做的
- 破解付费墙或绕过访问控制
- 高频滥用式抓取
- 访问境外网站（YouTube、Facebook等）
- 保存搜索缓存、临时文件等非最终资源
- 静默下载用户未确认的资源
- 传播或分享下载的资源（仅供个人学习）
