# resource-intent · 需求理解与查询生成

## 我是谁

**上游**：无（第一个阶段，直接接收用户需求）
**下游**：resource-search（把查询指令组传给搜索调度器）
**阶段编号**：stage 1

核心职责：把家长模糊、口语化的需求，翻译成一组能直接去搜的关键词。
不预设分类，不强制用户选类别，核心是"翻译器"而不是"分类器"。

---

## 执行前准备

### 1. 确认参数

从 flow 传入的参数中获取：
- `{session_dir}`：会话目录路径（绝对路径）
- `{output_file}`：本阶段输出文件名（通常是 `stage1_intent.json`）

> 💡 本阶段是第一个阶段，没有上游输入文件，直接接收用户的原始需求。

### 2. 准备工作目录

确认 `{session_dir}` 目录存在，如果不存在就创建。

---

## 执行步骤

### 第一步：接收并理解用户原始需求

**输入**：用户的自然语言需求文本（从对话上下文中获取）

**需要做的判断**：
1. 用户需求是否已经足够具体？
2. 是否需要澄清？

**判断规则**：
- ✅ **足够具体**：明确说了主题、年龄/年级、资源类型中的至少 2 项 → 直接进入第三步
- ❌ **不够具体**：只有模糊的需求（如"帮我找点学习资源"）→ 进入第二步澄清

> 📖 详细判断规则见：`./references/需求拆解规则.md` 第三节

---

### 第二步：需求澄清（最多 2 轮）

通过 1-2 轮对话，把模糊需求收敛到可搜索的具体主题。

**第 1 轮（必问）**：把核心诉求搞清楚
- 用开放式问题引导，不要用封闭式选项
- 例如："想找哪方面的学习资源呀？" 而不是 "要语文还是数学？"

> 📖 话术选择见：`./references/澄清话术库.md`

**第 2 轮（可选，最多 1 个）**：补充最关键的一个信息
- 优先级：使用场景 > 期望效果 > 年龄/基础 > 其他偏好
- **第 3 轮及以后：禁止**，宁可搜不准也不要问烦了

**澄清结束条件**：
- 用户明确了核心主题
- 或者已经问了 2 轮
- 或者用户说"就这样吧，先搜搜看"

---

### 第三步：语义理解与槽位抽取

从用户的需求描述中，提取关键信息。

**需要抽取的槽位**：
- `core_topic`：核心主题（如"三年级数学"、"古诗启蒙"）
- `target_age`：目标年龄范围（如"6-8岁"）
- `grade_level`：年级（如"小学二年级"）
- `difficulty`：难度偏好（入门 / 进阶 / 系统）
- `format_preferences`：资源形态偏好（视频 / 音频 / 文档 / 图文）
- `source_preference`：来源偏好（不限 / 官方优先 / 视频平台优先）
- `use_scenario`：使用场景（如"睡前听"、"课后练习"）

> 📖 槽位定义与抽取规则见：`./references/需求拆解规则.md` 第四节

---

### 第四步：默认补全

用户未明确的维度，按通用最优策略自动补全。

**默认补全规则**：
- 年龄/年级：如果用户没说，根据主题推测（如"古诗"默认"6-12岁小学全年级"）
- 难度：默认"入门"
- 资源形态：默认"视频+图文"（覆盖面最广）
- 来源：默认"不限"
- 搜索模式：默认"标准模式"

> 📖 完整补全规则见：`./references/需求拆解规则.md` 第五节

**重要**：所有自动补全的假设，都要记录到 `assumptions` 数组里，最后要告诉用户。

---

### 第五步：五维拆解生成查询

按「核心主题、资源形态、受众难度、来源倾向、使用场景」五个维度，生成差异化查询指令。

**要求**：
- 单需求至少生成 **10 个**差异化查询
- 覆盖至少 **3 种**资源形态

**查询分级**：
1. **核心查询（core）**：优先级最高，必须搜，3-5 个
2. **官方定向（official）**：去白名单官方站点搜，2-3 个
3. **形态定向（format）**：分别限定不同资源形态，3-5 个
4. **长尾补充（longtail）**：优先级较低，有空再搜，2-3 个

> 📖 五维拆解法详见：`./references/需求拆解规则.md` 第六节
> 📖 主题扩展词表见：`./references/主题扩展词表.md`

**每个查询的格式**：
- `text`：查询关键词字符串
- `tier`：优先级分级（core / official / format / longtail）
- `format_hint`：资源形态提示（视频 / 音频 / 文档 / 图文 / 不限）

---

### 第六步：去重排序与输出准备

合并相似查询，按优先级排序，准备写入输出文件。

**需要整理的内容**：
1. 需求一句话总结（`summary`）
2. 核心主题（`core_topic`）
3. 分级查询列表（`queries`）
4. 目标年龄/年级（`target_age` / `grade_level`）
5. 难度偏好（`difficulty`）
6. 资源形态偏好（`format_preferences`）
7. 来源偏好（`source_preference`）
8. 搜索模式（`search_mode`）
9. 默认假设清单（`assumptions`）

---

### 第七步：写入输出文件

将结果写入 `{session_dir}/{output_file}`（通常是 `stage1_intent.json`）。

**文件格式**（三层结构）：

```json
{
  "_meta": {
    "stage": 1,
    "session_id": "从 session_dir 中提取或生成",
    "skill": "resource-intent",
    "created_at": "当前时间（ISO 8601 格式）",
    "input_from": null
  },
  "_summary": {
    // 给 flow 看的摘要
  },
  "data": {
    // 给下游 search 用的完整数据
  }
}
```

---

#### _summary 部分（flow 读这个做调度）

**必须写入的字段**：
- `core_topic`：核心主题（字符串）
  - 示例："三年级数学练习题"
- `query_count`：查询总数（数字）
  - 示例：12
- `target_age`：目标年龄范围（字符串）
  - 示例："8-9岁"
- `search_mode`：搜索模式（字符串：standard / exhaustive）
  - 示例："standard"

> 💡 _summary 必须精简，flow 只读前几十行就知道结果怎么样。

---

#### data 部分（下游 search 读这个）

**必须写入的字段**：

- `summary`：一句话需求总结（字符串）
  - 示例："家长想给三年级孩子找数学练习题，优先找视频讲解和可打印的练习题"

- `core_topic`：核心主题（字符串）
  - 示例："三年级数学"

- `queries`：查询列表（数组）
  - 每个元素包含：
    - `text`：查询关键词（字符串，✅必选）
    - `tier`：优先级分级（字符串，core/official/format/longtail，✅必选）
    - `format_hint`：资源形态提示（字符串，⚠️可选）

- `target_age`：目标年龄范围（字符串，✅必选）
  - 示例："8-9岁"

- `grade_level`：年级（字符串，⚠️可选）
  - 示例："小学三年级"

- `difficulty`：难度偏好（字符串，✅必选）
  - 可选值：入门 / 进阶 / 系统

- `format_preferences`：资源形态偏好（数组，✅必选）
  - 示例：["视频", "文档"]

- `source_preference`：来源偏好（字符串，✅必选）
  - 可选值：不限 / 官方优先 / 视频平台优先

- `search_mode`：搜索模式（字符串，✅必选）
  - 可选值：standard / exhaustive

- `assumptions`：默认假设清单（数组，✅必选）
  - 记录所有自动补全的假设，让用户知道我们做了哪些猜测
  - 示例：["假设目标年龄为8-9岁（三年级）", "假设难度为入门级"]

---

## 完成后

### 1. 确认输出

确认 `{session_dir}/{output_file}` 已成功写入。

### 2. 向用户展示需求确认

用友好的方式向用户展示理解结果，格式如下：

```
【需求理解】
一句话总结：用 1-2 句话概括用户的核心诉求

【核心主题】XXX

【搜索参数】
- 🎯 查询总数：XX 个
- 📋 资源形态：视频、图文、文档...
- 👶 目标年龄：X-X 岁（用户明确 / 默认假设）
- 📊 难度偏好：入门/进阶/系统（用户明确 / 默认假设）
- 🏢 来源偏好：不限/官方优先/视频平台优先（用户明确 / 默认假设）
- ⚡ 搜索模式：标准模式 / 穷尽模式
- 💡 重点方向：（比如"优先找动画视频"、"重点搜官方站点"）

【假设说明】
- ✅ 用户明确：列出用户明确说过的信息
- 💡 默认假设：列出模型自动补全的假设（如果不对可以调整）
```

### 3. 通知 flow

向 flow 返回执行结果，只返回 _summary 的内容：

```
✅ 已完成需求理解
📄 输出文件：{output_file}
📊 摘要：
- 核心主题：{core_topic}
- 查询数量：{query_count} 个
- 目标年龄：{target_age}
- 搜索模式：{search_mode}
```

> 💡 **重要**：只返回 _summary，不要在上下文中展开完整的 data（查询列表等）。
> 完整数据已经写入文件，下游 search Skill 会去读。

## 关键原则

### 澄清原则
- **最少澄清**：能不问就不问，能猜就猜，猜了要说明假设
- **一次一问**：一轮只问一个问题，不要连发三问
- **开放引导**：用开放式问题引导，不要用封闭式选项框住用户
- **最多两轮**：最多问 2 个问题，问不完就用默认值
- **搜索优先**：搜索的成本比追问低，70% 清楚就可以开搜

### 拆解原则
- **语义优先**：用语义理解抽取意图，不做关键字匹配
- **穷尽召回**：多角度、多形态扩展，宁可多不可漏
- **假设透明**：使用默认假设时，必须明确告知用户

---

## 适用范围

面向 3-12 岁儿童成长相关的所有需求，包括但不限于：
- 学科学习、科普启蒙、人文历史
- 艺术美育、思维训练、兴趣拓展
- 习惯品格、情绪管理、安全教育
- 任何有助于孩子成长的内容
