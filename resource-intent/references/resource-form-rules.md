# 资源形式与交付要求

本规则用于理解用户对资源呈现和交付方式的表达。它只影响语义简报、证据和 requirements，不生成搜索任务。

## 三类表达

### 内容形态

例如动画、纪录片、公开课、试卷、练习册、绘本、课件、音频故事、互动游戏、实验和手工教程。

形态是资源“长什么样”，不等于资源作用：

- 动画是形态，“解释分数概念”是作用；
- 练习册是形态，“提供配套练习”是作用；
- 纪录片是形态，不自动代表系统学习或兴趣拓展。

### 文件格式

只有真实格式名称才算文件格式，例如 PDF、DOCX、PPTX、EPUB、MP3、MP4、ZIP。扩展名统一大写，不保留前导点。

“电子版”“高清版”“打印版”“可下载”不是文件格式。

### 使用或交付条件

例如可打印、可下载、在线播放、适合路上听、时长不超过十分钟。这些进入 clarified_need；用户明确要求时同时进入 requirements。

## 要求强度

- “只要 PDF”“必须可打印” → `must`；
- “最好有动画”“优先可下载” → `prefer`；
- “不要视频”“不接受付费内容” → `exclude`。

保留原语气，不把具体形态自动升级成硬要求。用户只说“找动画”表示目标资源形态是动画，可在简报中明确；是否记为 must 取决于原话是否表达不可妥协。

## 开放形式

“形式都可以”“什么类型都行”是用户明确授权开放收集，应写入 clarified_need，并记录为事实证据：

```json
{
  "statement": "用户不限定资源形式",
  "quote": "形式都可以"
}
```

用户完全没提形式时，不增加 requirement，也不默认视频、文档或音频。开放授权与未指定不同，但二者都不要求 Search 覆盖所有形式。

## 禁止事项

- 不因主题自动补充推荐形态；
- 不把“课程”“资料”自动解释为系统学习；
- 不把 PDF、视频或练习题拼成搜索句；
- 不为某种形式选择平台；
- 不从“可打印”擅自推断 PDF。
