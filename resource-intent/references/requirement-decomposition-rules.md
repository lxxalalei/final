## 一、核心思想

### 澄清不是目的，搜得到才是
澄清不是为了"分类准确"，而是为了"把需求描述清楚，让下游能搜准"。
70% 清楚就可以开搜，用户不满意再调整。**搜索的成本比追问的成本低。**

### 从"分类器"到"翻译器"
不预设分类，不强制用户选类别。
核心是把家长模糊、口语化、跳跃的需求，翻译成结构化的需求描述，交给下游 search 去生成查询。

### 适用范围
面向 3-12 岁儿童成长相关的所有需求，包括但不限于：
学科学习、科普启蒙、人文历史、艺术美育、思维训练、兴趣拓展、习惯品格、情绪管理、安全教育……

## 二、整体流程

```
用户提出需求
    ↓
需求清晰度判断
    ├─ 够清楚 → 直接进入槽位抽取
    └─ 不够清楚 → 进入澄清环节
    ↓
需求澄清（最多 2 轮）
    ├─ 第 1 轮：核心诉求澄清
    └─ 第 2 轮：补充关键信息（可选）
    ↓
槽位抽取 + 默认补全
    ↓
输出结构化需求描述（写入 stage1_intent.json）
```

## 三、需求清晰度判断

### 不需要澄清的情况（直接跳过）

满足以下任一条件，视为需求足够具体：

✅ **有明确的主题词**
- "三年级数学四则混合运算练习题"
- "儿童恐龙科普动画"
- "宝宝情绪管理绘本"

✅ **有明确的问题指向**
- "孩子计算总是粗心怎么办"
- "有没有适合 5 岁孩子的编程启蒙"
- "想让孩子学围棋，入门看什么"

✅ **用户说"随便""都可以""你看着办"**
- 直接按默认值处理，不要追问

### 需要澄清的情况（进入第 1 轮）

满足以下任一情况，视为需求模糊：

❌ **只有大品类，没有具体方向**
- "我想让孩子学点音乐"
- "有没有好的学习资源推荐"
- "想给孩子找点科普的看看"

❌ **问题太笼统，不知道具体痛点**
- "孩子数学不好"
- "孩子不爱看书"
- "想培养孩子的专注力"

❌ **需求歧义，可能有多种理解**
- "学编程" → 是 Scratch？Python？还是机器人编程？
- "学英语" → 是口语？单词？还是绘本阅读？

### 判断原则
**拿不准的时候，先搜一版试试，不要上来就问。**
用户看了结果再说"不是这个"，再追问澄清也不迟。

## 四、两轮澄清工作流

### 第 1 轮：核心诉求澄清（必问）

**目标**：把模糊的大方向，收敛到具体可搜索的主题。

**怎么做**：
1. 先复述你理解的需求，表示你在认真听
2. 用开放式问题引导用户说具体
3. 给 2-3 个方向做参考，但不要用封闭式选项

**判断是否够了**：
- 用户回答后，能提炼出 2-3 个核心搜索词 → 够了
- 还是很模糊，完全不知道搜什么 → 可以再引导一句，但不要超过第 2 轮

### 第 2 轮：补充信息（可选，最多 1 个）

**目标**：补充一个最关键的信息，大幅提升搜索准确率。

**什么时候问**：
- 核心主题清楚了，但有一个关键信息完全缺失，且对结果影响很大

**问什么（优先级从高到低）**：
1. **使用场景**（孩子自己看？家长陪？路上听？）→ 决定资源形态
2. **期望效果**（启蒙？系统学？应对考试？）→ 决定资源深度
3. **孩子年龄/基础** → 决定难度
4. **其他偏好**（时长、形式、预算等）→ 一般不问

**注意**：
- 第 2 轮最多问 1 个问题，问完就停
- 不要连环追问，用户会烦

### 第 3 轮及以后：禁止
- 绝对不要问第 3 个问题
- 信息不够就用默认值，搜出来用户不满意再调整
- 用户的耐心比搜索准确率更宝贵

## 五、澄清反模式（这些坑不要踩）

### ❌ 反模式 1：一上来就问年龄
**错误**："孩子多大了？"
**为什么不好**：很多家长反感，觉得"你先给我看看有啥，我再判断适不适合"。
**正确做法**：先按默认年龄搜，用户说不合适再调整。

### ❌ 反模式 2：让用户选分类
**错误**："你要找学科类、科普类还是艺术类？"
**为什么不好**：家长可能自己都不知道算哪类，而且你的分类可能漏了。
**正确做法**：用开放式问题引导，让用户自己说方向。

### ❌ 反模式 3：连环追问
**错误**："孩子多大？几年级？学过吗？喜欢什么形式？预算多少？"
**为什么不好**：用户直接跑了，体验太差。
**正确做法**：最多问 2 个问题，问完就停。

### ❌ 反模式 4：追求 100% 准确
**错误**：非要把所有信息都问清楚才开始搜。
**为什么不好**：效率太低，用户等不及。
**正确做法**：70% 清楚就开搜，用户不满意再调整。

### ❌ 反模式 5：用专业术语
**错误**："你需要的是学科同步类还是素养拓展类？"
**为什么不好**：用户听不懂，有距离感。
**正确做法**：用大白话，像朋友聊天一样。

## 六、槽位定义与抽取规则

### 什么是槽位
槽位（Slot）是从用户自然语言中抽取的结构化信息。每个槽位代表需求的一个维度。

### 输出槽位（对应 data 字段）

| 槽位 | data 字段名 | 说明 | 示例 |
|------|------------|------|------|
| 核心主题 | `core_topic` | 核心搜索主题 | 四则混合运算、唐诗、恐龙、英语启蒙 |
| 目标年龄 | `target_age` | 学习者年龄范围，3-12 岁 | "5 岁" → "5岁"；"8-9岁" → "8-9岁" |
| 年级 | `grade_level` | 年级 | 小学三年级、幼儿园大班 |
| 主题类型 | `theme_type` | 主题分类标签 | 科普 / 学科 / 古诗语文 / 思维训练 / 艺术美育 / 习惯品格 / 兴趣拓展 / 综合 |
| 难度偏好 | `difficulty` | 入门 / 进阶 / 系统 | 用户说"零基础" → 入门；"提高" → 进阶 |
| 资源形态偏好 | `format_preferences` | 资源类型偏好 | ["视频", "文档"]、["音频"] |
| 来源偏好 | `source_preference` | 不限 / 官方优先 / 视频平台优先 | 用户说"官方的" → 官方优先 |
| 使用场景 | `use_scenario` | 孩子怎么用这个资源 | 孩子自主看、亲子共读、路上听、打印练习 |
| 搜索模式 | `search_mode` | standard / exhaustive | 用户说"多找点" → exhaustive；默认 standard |

### 抽取原则
⚠️ **重要纪律**：
1. **只在用户明确表达时才填**，不要自行假设
   - 错误示例：用户说"英语课程" → 不要自行填 `format_preferences: ["视频"]`
   - 正确做法：`format_preferences` 留空，由默认假设填充
2. **语义抽取，不是关键字匹配**
   - "孩子数学跟不上" → `difficulty: "入门"`（需要基础巩固）
   - "想提前学一下下学期内容" → `difficulty: "进阶"`（预习提高）
   - "找点题练练手" → `difficulty: "进阶"`（练习强化）
3. **不确定的就留空**，不要硬猜，后续由默认假设填充

## 七、默认补全规则

当用户信息不完整或跳过追问时，使用以下默认值，并**明确告知用户**。

| data 字段 | 默认值 | 说明 |
|-----------|--------|------|
| `target_age` | 6-8 岁（小学低年级） | 儿童资源的主流受众 |
| `difficulty` | 入门 | 大多数家长找的是入门内容 |
| `format_preferences` | ["视频", "图文"] | 覆盖面最广的两种形态 |
| `source_preference` | 不限 | 不做来源限制 |
| `use_scenario` | （留空） | 场景信息通常不影响搜索策略的核心判断 |
| `search_mode` | standard | 标准模式够用 |

### 搜索模式判定

- `standard`（默认）：大多数需求，用户没特别说"多找"
- `exhaustive`（穷尽模式）：满足以下任一条件时切换——
  - 用户说"多找点""尽量全""搜全面一点""所有相关的"
  - 主题比较冷门/小众（如"少儿编程 scratch 入门"），担心搜不到
  - 需求很宽泛（如"适合 5 岁的科普"），需要多角度探索

### 年龄段未明确
- 按默认值 6-8 岁处理
- 同时在 assumptions 中记录"假设年龄为6-8岁"
- 如果主题明显偏高龄（如"方程""编程"），可以适当上调到 9-12 岁

### 资源形态未明确
- 默认覆盖视频和图文两种形态
- 学科类需求可适当追加"文档"形态（练习题、试卷等）

### 难度未明确
- 默认"入门"
- 如果主题本身偏进阶（如"奥数""竞赛"），按主题推断

### 假设说明话术
> "基于你的描述，我做了以下假设：
> - 孩子大约 6-8 岁（小学低年级）
> - 主要是兴趣启蒙和入门
> - 视频、图文形式都可以
>
> 如果这些假设不对，你可以随时告诉我调整。"
