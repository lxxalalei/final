# Intent 语义简报规则

## 1. 理解目标

Intent 输出的是资源收集需求的完整语义简报，不是槽位集合、关键词列表或搜索计划。

模型需要理解：孩子要学习什么、资源要支持什么任务、哪些学习者条件会影响适配、怎样使用资源，以及用户明确提出了什么要求。信息没有出现时保持开放，不为简报看起来完整而补全。

## 2. 学习内容边界

学习内容可以是：

- 学科知识或知识点：分数、古诗、自然拼读、太阳系；
- 兴趣主题：恐龙、航天、历史人物；
- 学科能力：阅读理解、写作、英语口语、计算；
- 实践能力：绘画、编程、实验操作、乐器演奏。

不把以下内容转换为学习主题：

- 学习方法：审题、笔记、背诵、检查或答题方法；
- 学习过程管理：专注力、时间管理、作业习惯、拖延；
- 泛化的行为、情绪、亲子关系或家庭教育问题。

如果请求同时包含范围外判断和明确学习内容，例如“孩子总粗心，想找二年级口算练习”，简报只把“二年级口算练习”作为收集对象，不把“粗心”写成诊断或学习主题。

## 3. 需求完整性

能够识别学科，不等于能够形成资源收集任务。判断是否存在“收集锚点”：

- 内容已经具体到可形成相对一致的结果集；
- 学段、年级或知识范围限定了内容；
- 学习任务说明了资源用途；
- 资源形式、作用或硬要求足以指导取舍；
- 用户明确要求全范围覆盖、资源概览或开放探索。

没有锚点时，Search 只能自行决定收集什么，Intent 应澄清。

例子：

- “帮我找一些小学数学资料”没有锚点，需要澄清；
- “找四年级数学同步练习”有年级、任务和形式，可以继续；
- “找恐龙科普动画”有具体主题和形式，可以继续；
- “覆盖整个小学阶段的数学资源，先看有哪些类型”明确授权全范围探索，可以继续；
- “孩子数学不好，找点资料”既没有具体内容，也没有明确范围，需要澄清。

## 4. 语义简报写法

`clarified_need` 应让一个没有参加前文对话的 Search 模型准确理解当前需求。

写作要求：

- 使用完整自然语言，不罗列内部字段名；
- 先说明要收集的学习内容和范围；
- 再说明已知的学习任务、学习者条件和使用方式；
- 把用户明确要求写清楚，但不要改变强度；
- 需要澄清时，说明当前理解和唯一未解决的关键分叉；
- 对未指定的信息使用“未限定”或直接不写，不替用户作决定。

不得写入：

- 平台和来源选择；
- 查询词、同义词或扩展词；
- 搜索数量、优先级和资源组合；
- 具体候选质量判断；
- 用户未表达的年龄、教材、语言、费用或媒介偏好。

## 5. 事实证据

`evidence` 中每项包含：

- `statement`：模型从原话确认的事实；
- `quote`：支持该事实的最短用户原话。

一个 statement 可以对原话做必要归一化，但不能扩大含义：

- “四年级数学” → “资源适用于小学四年级数学”；
- “上学路上听” → “资源需要适合通勤收听”；
- “最好有答案” → 不是普通事实，应进入 `requirements`，强度为 `prefer`。

不要把推断、常识或搜索策略放入 evidence。多个用户事实分别记录，方便下游核对。

## 6. 用户要求

`requirements` 保存下游必须继承的明确要求：

- `text`：归一化后的要求；
- `strength`：`must`、`prefer` 或 `exclude`；
- `evidence`：用户原话。

例子：

| 用户原话 | text | strength |
|---|---|---|
| “只要免费的” | 资源必须免费 | must |
| “最好有答案” | 优先选择带答案的资源 | prefer |
| “不要视频” | 排除视频资源 | exclude |
“形式都可以”表示明确授权，不等于没有信息；把它写入 clarified_need 和 evidence，不将其伪装成必须覆盖所有形式的硬要求。

不要把模型认为有帮助的讲解、练习、官方来源或中文资源写成 requirement。

## 7. 假设

只有为了继续流程且不会改变需求本质时才使用 `assumptions`。假设必须可被用户后续覆盖。

通常不要默认年龄、年级、教材、语言、费用、资源形式或学习任务。Search 自己拥有的搜索预算和覆盖策略也不是 Intent 假设。

## 8. 多目标与冲突

相关、主次或独立的多个学习内容都可以完整写入简报，不强行压成一个主题，也不自动要求用户二选一。

只有以下情况需要澄清：

- 用户事实互相冲突且会改变适配；
- 硬要求互相冲突；
- 当前执行必须确定优先级，否则只能任意取舍。

## 9. 输出前检查

1. Search 是否能仅凭 clarified_need 理解要收集什么？
2. 是否存在足以指导取舍的收集锚点？
3. 用户主动授权的宽泛探索是否被保留？
4. 是否把范围外问题或模型诊断写成学习内容？
5. evidence 是否都能由 quote 直接支持？
6. requirements 是否保持用户原有强度？
7. 是否泄漏了平台、查询或资源组合决策？
