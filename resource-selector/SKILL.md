# resource-selector · 质量筛选与用户选择

## 我是谁

**上游**：resource-platforms（搜索执行层，返回去重后的原始结果）
**下游**：resource-downloader（下载调度器）
**阶段编号**：stage 4

核心定位：**质量把关者 + 用户选择界面**——拿到 platforms 返回的去重结果后，先做五维质量评估打分，过滤掉低质量内容，精选排序，然后展示给用户选择。

---

## 核心职责

1. **质量评估**：按五维评分体系对每个资源打分（S/A/B/C 分级）
2. **过滤精选**：移除低质量、不相关、不安全的内容，精选出最终候选列表
3. **结构化展示**：将精选候选按平台、类型、质量分级分类展示
4. **灵活选择**：支持多种选择方式（编号、全部、按类型、按质量等）
5. **确认机制**：用户选择后先确认再下载，避免误操作
6. **结构化输出**：输出符合统一元数据规范的选定资源列表

---

## 执行前准备

### 1. 确认参数

从 flow 传入的参数中获取：
- `{session_dir}`：会话目录路径（绝对路径）
- `{input_file}`：上游输入文件名（通常是 `stage3_candidates.json`）
- `{output_file}`：本阶段输出文件名（通常是 `stage4_select.json`）

### 2. 读取上游输入

读取 `{session_dir}/{input_file}` 文件，提取其中的 `data` 部分。

> 💡 只需要读 `data`，`_meta` 和 `_summary` 可以忽略（那是给 flow 用的）

**需要读取的字段**（从 data 中）：
- `resources`：去重后的资源列表（数组，✅必选）
  - 每个资源包含基本元数据 + `platform_quality_score`（平台自评原始分）
- `intent_data`：透传的 intent 数据（对象，✅必选）
  - 需要从中提取 `core_topic`（核心主题）和 `target_age`（目标年龄）用于质量评估
- `search_summary`：搜索过程摘要（字符串，⚠️可选）
- `total_count`：去重后总数（数字，⚠️可选）

---

## 执行步骤

### 第一步：质量评估与分级 ⭐ 核心

对去重后的每个资源，按五维评分体系进行质量评估。

> ⚠️ 平台返回的 `platform_quality_score` 只是粗筛信号，必须基于五维体系重新评估打分，不能直接沿用。

**五维评分体系**：

| 维度 | 权重 | 说明 | 评估依据 |
|------|------|------|---------|
| 内容质量与完整性 | 25% | 内容是否丰富、系统、准确 | 标题、简介、时长/集数、是否成体系 |
| 适龄匹配度 | 25% | 是否适合目标年龄段 | 对照 `target_age`，看 `age_range`、`grade_level` |
| 权威可信度 | 20% | 来源是否可靠 | 平台属性（官方/机构/UGC）、作者、播放量 |
| 可获取性 | 20% | 能否下载/保存、是否免费 | `download_feasibility`、`is_free` |
| 安全与体验 | 10% | 是否适合儿童 | 语言、广告、内容安全性 |

**前置门槛（不进入评分，直接淘汰）**：
- 主题相关性：与 `core_topic` 不相关的资源直接淘汰
- 安全底线：有明显安全风险的直接淘汰

**质量分级**：
- **S 级**（强烈推荐）：综合得分 ≥ 90 分
- **A 级**（优质推荐）：综合得分 75-89 分
- **B 级**（可用推荐）：综合得分 60-74 分
- **C 级**（谨慎推荐）：综合得分 < 60 分

> 📖 完整评估标准见：`./references/quality-rubric.md`

**本步产出**：
- 每个资源增加：
  - `quality_score`：综合得分（数字，0-100）
  - `quality_level`：质量等级（S/A/B/C）
  - `quality_details`：各维度得分（对象，可选）

---

### 第二步：低质量过滤与精选

过滤掉低质量结果，精选出最终候选列表。

**过滤规则**：
1. 移除 C 级资源（除非候选特别少，不足 10 个时保留）
2. 移除非中文内容（英语学习等明确需求除外）
3. 移除明显广告、营销内容
4. 移除付费/VIP 且无法预览的内容
5. 移除境外网站、未知域名的内容

**精选数量**：
- 标准模式：20-25 个
- 穷尽模式：30-40 个

**排序原则**：
1. 质量优先：S 级 → A 级 → B 级 → C 级
2. 同质量内：下载可行性高的优先
3. 同平台内：按热度/播放量排序
4. 平台多样性：尽量保证多个平台都有代表

**本步产出**：
- `final_candidates`：精选后的候选资源列表（数组，按质量排序）
- `quality_dist`：质量分布（对象）
- `search_summary`：更新后的搜索摘要（含质量分布信息）

---

### 第三步：结构化展示

将精选候选展示给用户。

#### 排序原则

1. **质量优先**：S级 → A级 → B级 → C级
2. **同质量内**：下载可行性高的优先
3. **同平台内**：按热度/播放量排序

#### 分类方式

优先按**平台**分类展示，其次按**资源类型**分类。
如果资源数量多（>15个），可以先按平台分，每个平台内再按质量排序。

#### 数量展示

- 默认展示全部候选（标准模式20-25个，穷尽模式30-40个）
- 如果超过 30 个，可以先展示 TOP 20，再问用户是否要看更多
- 必须告诉用户总共有多少个候选

#### 字段说明

| 标识 | 字段 | 说明 |
|------|------|------|
| ⭐ S/A/B/C | 质量等级 | 本 Skill 五维评估后的最终质量等级 |
| 📍 平台 | 来源平台 | 用户一眼知道来自哪里 |
| 📊 难度 | 下载可行性 | 高/中/低，让用户有预期 |
| 👀 播放 | 播放/浏览量 | 侧面反映受欢迎程度 |
| ⏱️ 时长 | 时长/集数 | 视频/音频类显示 |
| 💡 推荐理由 | 内容简介 | 1-2句话说明为什么推荐 |
| 🔗 链接 | 来源URL | 用户可以自己先点开看看 |

#### 下载难度标识

| 等级 | 标识 | 说明 | 提示语 |
|------|------|------|--------|
| 高 | ✅ 高 | 基本可以成功下载 | "下载成功率高" |
| 中 | ⚠️ 中 | 可能需要重试或降级 | "可能需要重试，建议选1-2个备用" |
| 低 | ❌ 低 | 大概率下不了 | "下载难度大，可能只能保存摘要" |

**展示原则**：
- 难度为"低"的资源，必须明确提醒用户
- 建议用户搭配选择：高难度的选几个，中低难度的也选几个备用
- 如果用户选的全是低难度的，主动提醒并建议增加一些高难度的

### 第四步：用户选择与确认

#### 选择方式

**1. 编号选择**
- 单个：`1`
- 多个逗号分隔：`1,3,5`
- 多个空格分隔：`1 3 5`
- 范围：`1-5`（选1到5号）
- 混合：`1,3-5,7`

**2. 全部选择**
- 指令：`全部`、`全选`、`都要`、`所有`

**3. 按类型筛选**
- 指令：`视频`、`音频`、`文档`、`练习题`、`图文`

**4. 按质量筛选**
- 指令：`S级`、`A级`、`S和A级`、`高质量`

**5. 按平台筛选**
- 指令：`B站`、`喜马拉雅`、`知乎`

**6. 按下载难度筛选**
- 指令：`高难度`、`容易下的`、`稳的`

**7. 取消选择**
- 指令：`不要了`、`算了`、`取消`、`不下载了`

#### 确认机制

用户选择后，必须先确认再进入下载阶段。

**确认格式：**
```
✅ 已为您选择 X 个资源：

1. [资源1标题] [平台]
2. [资源2标题] [平台]
...

准备开始下载，确认吗？
• 回复"确认"开始下载
• 回复"取消"重新选择
• 回复"加几个"继续添加
• 回复"去掉X"去掉某个
```

---

### 第五步：写入输出文件

用户确认选择后，将选定结果写入 `{session_dir}/{output_file}`（通常是 `stage4_select.json`）。

```json
{
  "_meta": {
    "stage": 4,
    "session_id": "{session_id}",
    "skill": "resource-selector",
    "created_at": "ISO时间",
    "input_from": "stage3_candidates.json"
  },
  "_summary": {
    "total_candidates": 45,
    "filtered_count": 22,
    "selected_count": 5,
    "selection_mode": "manual",
    "by_platform": {"bilibili": 2, "ximalaya": 3}
  },
  "data": {
    "selected_count": 5,
    "selection_mode": "manual / all / by_type / by_quality",
    "resources": [
      {
        "// 说明": "保留上游全部字段 + 本阶段新增评估字段",
        "resource_id": "...",
        "title": "...",
        "type": "...",
        "platform": "...",
        "source_url": "...",
        "source_name": "...",
        "quality_level": "S/A/B/C",
        "quality_score": 92,
        "download_feasibility": "...",
        "...": "（上游的所有字段原样保留）"
      }
    ]
  }
}
```

- `_summary`（flow 读这个）：候选总数、过滤后数量、选中数量、选择方式、平台分布
- `data`（下游 downloader 读这个）：用户选中的资源列表
- **保留规则**：只做筛选不做裁剪，保留的每个资源要带过来上游的全部字段 + 本阶段新增的 `quality_level`、`quality_score`，一个字段都不能删

## 异常处理

### 用户输入无法识别

```
抱歉，我没理解您的选择 😅

可以这样选：
• 回复数字编号（如：1,3 或 1-5）
• 回复"全部"下载所有
• 回复"视频"只选视频类
• 回复"S级"只选S级
• 回复"不要了"取消下载
```

### 选的全是低难度的

主动提醒：
```
⚠️ 提醒：您选的 X 个资源里，有 X 个下载难度是"低"的，大概率可能下不了。

建议再选几个下载难度"高"或"中"的备用，避免都下失败了没的用。
需要我帮您推荐几个吗？
```

### 选的数量太多

如果选了超过 10 个，主动确认：
```
您选了 X 个资源，数量有点多哦，下载可能需要比较长时间。

确认要全部下载吗？
• 回复"确认"全部下载
• 回复"选前10个"只下载质量最高的10个
• 回复"取消"重新选择
```

## 关键原则

### 质量评估原则
1. **相关性优先**：不相关的内容质量再高也淘汰
2. **适龄匹配**：适合孩子年龄的才是好资源
3. **安全底线**：有安全风险的直接过滤掉
4. **可获取性**：同等质量下，能下载保存的优先
5. **重评而非沿用**：平台返回的 `platform_quality_score` 只是参考，必须基于五维体系独立评估

### 展示原则
1. **信息透明**：每个资源的关键信息（质量、难度、平台）都要明确展示
2. **选择灵活**：支持多种选择方式，满足不同用户习惯
3. **防误操作**：有确认机制，避免用户手滑选错
4. **友好提示**：对可能的问题（低难度、数量多）主动提醒
