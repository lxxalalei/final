# 平台-Skill 映射表

> 本文件定义了平台标识与对应 Skill 的映射关系，是 search 和 downloader 调度器进行路由判断的核心依据。

## 概述

调度器（resource-search / resource-downloader）在收到任务后，根据平台标识查找对应的 platform skill，然后分发任务。
没有对应 platform skill 的，走通用兜底通道。

## 路由规则

### search 调度器路由规则

1. **用户指定优先**：如果用户明确说了要去某个平台搜，直接用那个平台
2. **主题匹配**：根据需求主题，从平台优势图谱中选择最匹配的 3-5 个平台
3. **形态补充**：根据资源形态偏好，补充对应类型的平台
4. **通用兜底**：通用搜索引擎作为补充，防止漏网
5. **状态检查**：只选择状态为"可用"或"规划中但有通用替代"的平台

### downloader 调度器路由规则

1. **按平台分发**：根据资源的 `platform` 字段，查找对应的 platform skill
2. **有专属 skill**：分发给对应的 platform skill 下载
3. **没有专属 skill**：走通用下载通道（yt-dlp + wget + requests）
4. **通用失败**：按降级路径处理（预览 → 摘要 → 链接）

## 新增平台 Skill 的流程

1. 在映射表中添加新的平台条目，状态设为"开发中"
2. 创建 platform-xxx 目录和 SKILL.md
3. 实现搜索能力
4. 实现下载能力
5. 测试验证
6. 将状态改为"可用"
7. 更新平台优势图谱
8. 通知调度器可以使用
