# 平台能力与路由判断

平台不是固定套餐。先由需求产生搜索方向，再让平台按内容密度、独特性和执行可靠性竞争这些方向。运行事实以 `../config/platform-catalog.json` 和 `../../resource-platforms/references/platforms/` 为准。

## 可执行平台

### generic：全网基线，已验证

同时使用百度和 Bing，适合跨站发现：

- 官方、公共教育、博物馆、科技馆、图书馆、大学、专业机构和出版机构内容；
- 图文说明、原文、练习、活动说明、讲义、课件及可下载文件；
- 未接入平台或站点的公开页面；
- 同一主题的不同来源表达。

每份计划恰好包含一个 `generic/P0`。它不需要排在任务数组第一，也不意味着其他平台必须等它完成。

### smartedu：结构化课程与公共教育资源，已验证

优势是学段、学科、课程和知识点组织。适合系统课程、同步内容、学科知识结构和公共教育资源。查询应精确表达学段、学科与内容，但不要虚构教材版本或站内筛选参数。

### bilibili：视觉讲解与连续视频，已验证

优势是过程演示、实验现象、动画解释、朗读画面、纪录片和系列讲解。只有“看见过程或画面”确实增加价值时加入。用具体视觉任务搜索，不把“高播放”“高赞”写进查询。

### ximalaya：朗读、故事与连续音频，已验证

优势是朗读、跟读、故事、听书、儿歌和专辑式连续收听。声音本身是内容或用户有低屏幕场景时价值最高。用 `core=album` 搜系列，用 `core=track` 搜单篇；`free_only` 只在用户明确要求免费时使用。

### zhihu：专题解释与资源线索，需认证、已验证

适合需要较深入的概念辨析、主题背景或高信息量资源线索时补充。当前产品不收集学习方法、学习习惯或泛家长经验，因此不能因“家长视角”自动路由到知乎。只有其内容生态对当前学科主题有独特增益时使用。

### open163：公开课、讲座与纪录片，适配器尚未充分验证

适合较深入的人文、科学讲座、纪录片和公开课，不适合日常小学同步资料的常规覆盖。因当前真实搜索验证不足，通常作为 P2；只有独特内容价值明显时加入。

### weibo：机构动态与时效线索，需认证且尚未充分验证

适合机构发布、活动、展览、竞赛或近期公开资源线索，不是稳定的核心学习材料库。需求没有时效性或机构追踪价值时省略。

### douyin：单点短视觉演示，需认证且当前易触发验证

只适合短时间即可看清的单个动作、实验现象或操作片段。系统学习目标不应依赖它。当前执行可靠性低，通常省略；确有不可替代的短演示价值时才以 P2 探索。

## 尚不能成为独立任务的平台

`baiduwenku`、`xiaohongshu`、`cctv` 当前为 planned。确有价值时可由 generic 搜索其公开页面，例如针对文档、生活化活动经验或公共媒体内容做定向发现，但不得输出这些平台的独立任务。

## 路由原则

1. 优先让一个平台承担其最擅长且其他来源难替代的方向。
2. 已接入不等于必须使用；认证和运行风险要进入预算判断。
3. 平台之间若只是在重复主题关键词，删除预期相关密度或可靠性较低者。
4. 用户明确指定平台时，在不违反范围和执行边界的前提下保留；generic 仍提供跨站基线。
5. 媒介只是学习用途的实现方式，不按视频、音频、图文平均分配。
