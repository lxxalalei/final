# 面向资源搜集的查询设计

查询的目标是得到一组互补、有实际用途的学习资源。先定义每条查询想发现什么，再决定用什么词，不按字段模板机械拼接。

## 以资源作用拆分查询

从当前任务中动态选择若干真正有用的方向：

- 可靠的核心说明、原文、知识介绍或基础参考；
- 适合孩子理解的注释、例子、讲解或过程演示；
- 练习、应用、复习、自测或动手活动；
- 可阅读、保存、打印或反复使用的材料；
- 家长陪伴方法、资源选择方法或亲子使用建议；
- 与主题有关的故事、音频、延伸阅读或兴趣探索。

这不是固定清单。查询数量由需求决定；资源形态是实现用途的手段，不预设形态比例。

## generic 首轮查询

通常设计 3–5 条互补查询，每条承担不同作用：

1. 用主题本身发现总体资源和可靠来源。
2. 用一个关键学习行为或内容切面发现更可用的材料。
3. 用练习、阅读、活动、家长辅助等与当前任务相关的方向补足覆盖。
4. 需要时用 `site:` 定向可信来源或尚未接入的公开平台页面。
5. 只有具体文件确有使用价值时才使用 `filetype:`。

同一组查询交给百度和 Bing。各查询应承担不同的资源作用；搜索引擎摘要只作为候选线索。

## 专业平台查询

专业平台只搜索其有独特优势的部分：

- 视频平台：过程、动作、发音、朗读、实验或视觉变化确实需要看见时，写面向该示范的查询。
- 音频平台：朗读、跟读、听觉输入、故事或低屏幕场景确有价值时使用。
- 结构化课程平台：当前任务确实需要系统课程或学段资源时使用。
- 方法与经验平台：家长确实需要判断、陪伴或解决方法时使用自然问题表达。
- 短内容与动态平台：只承担单个示范、机构发布或活动线索等窄职责。

不同平台的查询应反映各自承担的资源作用，而不是套用统一后缀。

## 保留事实边界

- 核心主题在每条查询中必须可识别。
- 用户明确的 must 在相关查询中保留；prefer 用来增加方向，不偷换成硬条件。
- 年龄、年级、教材、免费、文件格式等只有在用户表达或确实能改善召回时才加入。
- Intent 的 `related_terms` 可以扩大内容切面，但不能替代核心主题，也不能伪装成用户要求。
- 无法由搜索接口验证的安全、完整性、费用和质量，留给 Selector 判断。

## 有效扩展判断

增加一个查询或限定词前，判断它是否改变预期结果集合、补充新的资源作用或提高相关性。以下情况通常没有新增价值：

- 只替换近义词，搜索目标没有变化；
- 多条查询重复相同限定条件但搜索目标没有变化；
- 因平台容易出结果而重复搜索相同内容；
- 加入当前证据和搜索目标都不需要的限定条件；
- 为计划看起来丰富而加入没有独特价值的平台。
