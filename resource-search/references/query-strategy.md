# 平台关键词生成方法

搜索词的目标是扩大有效召回，而不是展示模型做过多少字段分析。

## 从需求展开搜索角度

围绕当前主题选择真正有意义的几个方向：

1. **核心表达**：用户最自然的主题词及常见同义表达。
2. **内容组成**：这个主题包含哪些可独立搜索的知识或学习环节。
3. **学习行为**：理解、朗读、背诵、练习、实验、跟做、复习、查方法等。
4. **资料形态**：动画、讲解、故事、音频、课程、练习题、课件、文章等。
5. **使用场景**：睡前听、通勤、课堂、课后练习、亲子活动、打印使用等。
6. **来源和格式**：用户确实需要时再加入官方站、机构名、`site:` 或 `filetype:`。

不要求每个需求都覆盖全部方向。选择哪些角度取决于主题、用户目的和平台优势。

## 先决定平台任务，再写关键词

同一个主题在不同平台承担的工作不同，因此搜索词也不同。

以“小学古诗学习”为例：

- ximalaya：`小学古诗朗诵专辑`、`小学生必背古诗跟读`、`儿童古诗音频`
- bilibili：`小学古诗动画`、`儿童古诗意境讲解`、`小学生古诗逐句赏析`
- generic：`小学古诗 原文 注释 译文`、`小学古诗 学习资料`

这里没有必要先确定教材版本或具体年级，因为当前主题并不依赖这些信息。如果需求变成“三年级语文上册古诗同步复习”，这些维度才自然进入 smartedu 和其他平台的关键词。

## 各平台的语言习惯

- bilibili：围绕讲解、动画、课程、合集、纪录片、教程、过程演示组织查询。
- ximalaya：围绕故事、朗诵、跟读、音频课、专辑、睡前听、磨耳朵组织查询。
- smartedu：在课内或官方资源需求中使用学段、年级、学科、知识点、版本和册次。
- zhihu：将需求写成方法或问题表达，例如“怎么学”“怎么教”“为什么”“有哪些推荐”。
- douyin：聚焦一个能短时间演示的技巧、动作或步骤，关键词简短具体。
- weibo：围绕机构、活动、资料发布和分享线索搜索。
- open163：使用公开课、纪录片、讲座、人文或通识课程表达。
- generic：使用自然主题词结合内容角度、用途、站点和文件格式扩大跨站召回。

这些词是平台语言线索，不是强制后缀。比如 B站任务确实在找纪录片时才加入“纪录片”，不能为了命中画像而强行加入无关词。

## 查询之间如何形成差异

有效差异来自搜索目标的变化：

- `恐龙科普动画` 与 `恐龙灭绝原因讲解` 分别召回动画和具体知识解释。
- `古诗朗诵专辑` 与 `古诗跟读音频` 分别召回连续收听和跟读材料。
- `四年级数学同步课程` 与 `四年级数学知识点讲解` 分别召回系统课程和专题讲解。

仅把“孩子”换成“儿童”、把“教程”换成“教学”，通常没有扩大实际召回角度，不值得单独生成。

## 约束如何进入搜索词

- 用户明确要求“带答案”时，练习类查询可以加入“带答案”。
- 用户明确要求免费时，只有平台接口支持免费过滤才写入参数；其他平台仍正常搜索，由 Selector 核验费用。
- 用户排除视频时，不创建纯视频平台任务。
- 用户偏好官方时，可以增加官方来源方向，但不要因此删除其他有价值的平台。
- 用户说可打印时，可搜索“可打印”；没有明确文件格式时不要擅自改成 PDF。
- 用户明确 PDF/PPT/DOC 等格式时，generic 可以使用 `filetype:`。

约束应自然影响平台选择和关键词，不需要在每个搜索任务中重复复制完整 Intent。

## 通用搜索技巧

- 普通全网：`主题 + 内容角度或用途`
- 可信站点：`site:example.org 主题`
- 文件格式：`filetype:pdf 主题`
- 精确短语：当主题名称容易被拆散时使用双引号

`site:` 和 `filetype:` 用于 generic。不要把搜索引擎运算符发送给不支持它们的平台站内接口。

standard 通常给 generic 生成 2-3 个互补查询；exhaustive 可以增加更多内容角度、站点和文件格式。百度和 Bing 执行同一组 generic 查询，再由 Platform 合并结果。
